# comfy-gallery

ComfyUI 出图图库。自动索引 `output` 目录，点开任意一张图就能看到「配方」式元数据面板：提示词、模型、LoRA 与权重、每次采样参数。

独立页面，也可从 ComfyUI 顶栏按钮进入：

```
http://127.0.0.1:8188/gallery
```

[English](README.en.md)

## 为什么单独做一个

[ComfyUI-Lora-Manager](https://github.com/willmiao/ComfyUI-Lora-Manager) 的配方界面很好用，但图片必须先手动加进配方才能看到元数据。本包直接读取 ComfyUI 写进图片里的生成信息，省掉这一步：出完图就能翻，翻到哪张看哪张。

解析思路参考了 [ComfyUI-Sidebar-Gallery](https://github.com/TokenSpender/ComfyUI-Sidebar-Gallery)（读图内的 API 图，而不是扁平参数字符串），交互按配方面板组织。

## 安装

**ComfyUI-Manager**：搜索 `comfy-gallery` 安装，重启 ComfyUI。

**手动**：把本仓库放进 `ComfyUI/custom_nodes/`，重启 ComfyUI。

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/1730177143/comfy-gallery.git comfy-gallery
```

若仓库放在别处，用目录联接即可，不必复制：

```bat
cd ComfyUI\custom_nodes
mklink /J comfy-gallery D:\path\to\comfy-gallery
```

重启后 ComfyUI 顶栏会出现 **Gallery** 按钮，点开即在新标签打开图库；`Shift+点击` 用独立窗口打开。

首次打开会扫描整个输出目录，几千张图大约需要一到两分钟；期间顶部显示索引进度，已索引的部分可以先看。

## 使用

- **左侧栏**：`全部图片`、`收藏`，以及按目录层级列出的文件夹（带张数）；下方 `基模` 可一键筛选 Krea2 / SDXL / Illustrious 等家族。
- **顶部**：全库搜索（文件名、文件夹、提示词、模型名、LoRA 名、采样器名都能命中）、排序、`网格` / `瀑布流` 切换、刷新。
- **卡片**：左上角是基模徽章，紧跟一个工作流小图标（该图内嵌了工作流时才出现，点它直接发送到 ComfyUI）；右上角是收藏与删除；瀑布流下显示两行提示词摘要，网格模式显示文件名。
- **多选**：顶栏的勾选按钮进入多选模式，点卡片即选中；顶部条可 `全选`、批量`收藏`、批量`删除`，`Esc` 退出。
- **详情方式**：顶栏三档切换 —— `侧边显示`（默认，右侧面板）、`大图显示`（弹窗，左图右参数，两侧箭头翻页）、`只看原图`（全屏看图，`←` `→` 切换，不渲染参数）。
- **设置**：默认布局、每行数量（0 = 自动）、额外目录、是否包含视频、**纯看图模式滚轮切图**、点击空白关闭看图、每页数量、撤回时间、缓存目录、**扫描新文件 / 重构数据库**。
- **目录树**：条目多时可滚动，超过 12 个目录会在顶部出现筛选框（吸顶），输入即过滤。
- **滚轮切图**：默认关闭。打开后在看图模式里滚轮向下看下一张、向上看上一张（一次手势只切一张）；关闭时滚轮保持正常滚动。

快捷键：`/` 聚焦搜索，`Esc` 关闭放大图或收起面板，方向键在网格中移动。

## 面板内容

- **生成参数**：正向与负向提示词，可一键复制。
- **基模**：识别出的模型家族（由主模型 / UNET / CLIP 类型推断，仅靠 LoRA 推断时会注明）。支持 Krea2、**MOSS-Image**、Qwen Image、Flux、Wan、Hunyuan、LTX、MiniMax、Illustrious、NoobAI、Animagine、**Anima**、Pony、SDXL、SD3、SD 1.5 / 2.1，以及 NovelAI（`NAI`）。

识别顺序：模型文件名 → LoRA 路径 → **图片文件名**。有些导出器（例如某些 Image Saver 配置）不写模型名，只把模型留在文件名里（如 `Moss25-865045361575048_00001_.png`），这时会用文件名兜底，并在详情面板标注「由文件名推断」。识别不出的仍显示 `UNK`，可手动指定。
- **模型**：主模型 / UNET、VAE、CLIP（含类型与 CLIP 跳过层）。
- **LoRA**：名称、权重、是否启用；未启用的行会淡化并标记 off。
- **采样器**：每个采样节点一张卡片，含步数、CFG、采样器、调度器、种子、重绘幅度、步数区间；多次采样或高噪 / 低噪分离的工作流会各自列出。
- **其他参数**：ControlNet、放大模型与倍数、检测器、输入图、基础尺寸等。
- **原始元数据**：展开可看完整 JSON。

数值取自解析连线后的真实值，所以由 Seed 节点、数学节点、比例选择器算出来的参数也能显示；基础尺寸由比例选择器推算时带 `≈` 标记。

底部动作：复制提示词、**发送到 ComfyUI**、下载原图、移到回收站。

### 索引维护

| 操作 | 作用 |
| --- | --- |
| 自动 | ComfyUI 每保存一张图，立即索引这一张（不扫描整个 output） |
| 扫描新文件 | 补新增、清掉已删除的条目 |
| 重构数据库 | 丢掉整个索引重读一遍，适合在 output 里大批量搬动文件之后 |

手动指定的底模单独存表，**扫描、重构、文件搬动都不会丢**；根目录不可读时会跳过清理，不会因为一块硬盘没挂上就删掉它的记录。

### 底模修正

详情面板的「基模」下拉可以手工纠正。修正会**自动同步到同一主模型的全部图片**（按 checkpoint / UNET 文件名分组），提示条会写明改了多少张；选「不限」可恢复自动识别。

「发送到 ComfyUI」把该文件内嵌的工作流作为**一个新的工作流标签页**打开在 ComfyUI 里，当前正在编辑的标签页不受影响，页面也不会刷新或跳转——图库通过 BroadcastChannel 把工作流交给已打开的 ComfyUI 页面，由随附的前端扩展调用 `app.loadGraphData()` 新建标签页载入。

如果此时没有任何 ComfyUI 页面打开，才会新开一个。文件里没有工作流时按钮为禁用状态。

## 支持的元数据来源

| 来源 | 说明 |
| --- | --- |
| ComfyUI `prompt` | 原生 `SaveImage` 等写入的 API 图，解析最完整 |
| Automatic1111 `parameters` | ComfyUI-Image-Saver 等写入的扁平参数串，含 `<lora:...>` 标签 |
| NovelAI `Comment` | NovelAI 写入的 JSON（提示词、uc、steps、scale、seed、sampler、尺寸），旧版 `sd-metadata` 同样支持 |
| 仅 `workflow` | 只存了编辑器工作流时按核心节点近似读取，面板标注为近似 |
| 无元数据 | 仍然列出并可浏览，面板标注「无元数据」 |

## 基模识别不准时

自动识别不出来的图会在侧栏「基模」里计入 `未识别`。打开该图的详情，在「基模」一栏用下拉框手动指定即可；手动指定会被记住，重建索引也不会被覆盖，旁边的 `恢复自动识别` 可回到自动结果。

## 收藏与删除

- 收藏存在设置文件里，换浏览器或重启都保留；左侧「收藏」即为收藏夹视图。
- **删除有撤回窗口**：点删除后不会立刻删除，卡片会变暗并显示倒计时，顶栏的撤回按钮变红并显示数量。
- 点撤回按钮打开「即将删除」面板，里面只列出等待删除的图片：可以逐张`撤回`、开启`选择`后批量撤回，或`全部撤回`。
- **面板打开期间计时暂停**（服务端同步冻结，不是本地障眼法），关掉面板后继续倒数。
- 窗口长度在设置里改：默认 60 秒，可设 0–600 秒；设为 0 表示关闭撤回，删除立即生效。
- 倒计时结束后文件被移动到该根目录下的 `.gallery-trash/<原相对路径>`，仍可手动还原。

## 数据与隐私

索引数据库和缩略图缓存存放在 ComfyUI 用户目录下：

```
ComfyUI/user/comfy-gallery/
├── index.db     # 文件索引与解析结果
├── settings.json
└── thumbs/      # 缩略图缓存
```

全部留在本机，不联网、不外传。删掉该目录即可重建，不影响任何原图。

## 已知限制

- 若 ComfyUI 启动时带了 `--disable-metadata`，图片里不会有生成信息，面板只能显示「无元数据」。
- JPEG / WebP 依赖 EXIF 的 `UserComment`；部分保存节点不写，这类图同样看不到配方。
- 只有 `workflow` 而没有 `prompt` 的文件，参数按核心节点的 widget 顺序近似读取，自定义节点可能读不到。
- 基模徽章是推断结果，重命名过的模型可能识别不出（此时不显示徽章）。
- 本包只读索引、只提供上述单个文件操作，不做批量删除、评分或标签管理，也不注册任何节点。
